附录 G　情景库与可复现框架

本附录把第 10 章的三个情景固化为一个可复现、可扩展的数据结构，使第三方能够独立重算、修改参数、增补情景。它不是一套“预测模型”，而是一台“假设审计机”：任何风险判断若要被复用，必须先把它的因数、数据质量与时间窗口显式写下来。这正与全书“登记—监测—核对”的方法论一致。

G.2　计算流程

参数到结论的计算流程如下（与正文式 10.1—11.3 一致）：

AC名义 = ¼(Reserves + Substitutability + Diversification + Θ) × (1 − κ/5)(G.1)
AC有效 = AC名义 × min(1, C)(G.2)
Risk(S) = Hazard × Exposure × (1 − AC有效)(G.3)

式(G.2)是本书对风险分解的实质增补：用 C = 1/τ 对名义适应能力作时间折扣。当 C ≥ 1 时无折扣（S1）；当 C ≪ 1 时，即使名义适应能力很高，有效值也趋近于零（S3）。

G.3　可复现的数据结构

为了让第三方能够审计，情景库以一个简单的数据结构定义。下面给出其字段（Python 数据类的形式；实际代码随发布包的分析目录提供）：

@dataclass
class RiskScenario:
    name: str                    # 情景名称
    hazard: float                # Hazard 概率 (0-1)
    exposure: float              # Exposure 比例 (0-1)
    reserves: float              # 缓冲评分 (0-1)
    substitutability: float      # 替代评分 (0-1)
    diversification: float       # 多元评分 (0-1)
    theta: float                 # Θ 评分 (0-1)
    kappa: float                 # κ 耦合 (0-5)
    t_min: float                 # 协调最小时间（天）
    t_available: float           # 可容许时间（天）
    quality: dict                # 各字段数据质量 A-E

    def tau(self): return self.t_min / self.t_available
    def controllability(self): return 1 / self.tau()
    def adaptive_capacity(self):
        nom = (self.reserves + self.substitutability +
               self.diversification + self.theta) / 4 * (1 - self.kappa / 5)
        return nom * min(1.0, self.controllability())
    def risk(self):
        return self.hazard * self.exposure * (1 - self.adaptive_capacity())
性质：代码结构说明（可复现）。注释：完整脚本见发布包之外的 analysis/ 目录（发布包按惯例不含代码，见 README）。字段设计的目标是让“未测”可以被显式标注，而不是被默认赋零。

G.4　如何扩展新情景

情景库被设计为开放结构。添加一个新情景只需四步：

  1. 定义 S：写出 Hazard 与 Exposure，并说明范围（单点／单国／系统）。
  2. 标定六因素：Reserves、Substitutability、Diversification、Θ、κ、τ；每个字段标注数据质量 A—E，无法测量者记为“未测”。
  3. 估时间窗：给出 Tmin 与 Tavailable 的量级，并说明依据（历史先例或程序记录）。
  4. 交付并登记：输出 Risk 与不确定性区间，并预登记“什么结果会推翻本情景的判断”。

G.5　局限与边界声明

警告 G.5.1　情景库不是预测机 情景库的所有数值都是假定的，不是对未来的预测。它的价值在于：当现实冲击发生时，可以立即用同一套参数化重算，并把“实际发生了什么”与“当初假定什么”逐条对照。它服务于事后校准，而非事前预言。任何把它当作预警系统直接驱动决策的用法，都超出了它的设计意图，也超出了本书的责任范围。
  1. 参数的主观性：Reserves 与 Θ 有客观数据支撑，但 τ 与 κ 的部分赋值依赖判断，质量标注必须随数值一起报告。
  2. 量纲的不可通约：τ 只能作序数使用（命题 4.1），情景间的 Risk 数值不可直接比较。
  3. 框架的失效区：当冲击为系统同步型（C ≪ 1）时，公式仍能计算，但其输出不应被解释为可操作的风险值（表 13.3）。
  4. 政治变量的外生性：协调是否发生是一个政治决策，情景库把它作为参数输入，而不试图预测它——这正是“I 不可测”这一边界的延续。

G.6　结语：从框架到工具，再回到问题

附录 F 与 G 把关于时间错配与可控性的诸章的理论转译成了工具。但工具的意义恰恰在于暴露理论解决不了的部分：当诊断表填不完、当 τ 无法给出数值、当政治协调无法被参数化时，使用者会一次次撞上同一个边界——时间与制度的错配。这不是工具的失败，而是它忠实反映的问题本身。

因此，本附录的最终建议与全书一致：用工具把能说清的写清楚，把说不清的显式留给判断。一个肯在空白处写“未测”的分析，比一个处处填满数字的分析，更接近科学。
